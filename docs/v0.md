# v0 application rail

## Product decisions

- `All` means product-visible sessions. Archived sessions are intentionally excluded.
- The 56px AppFrame rail is retained and treated as a candidate final posture, not a temporary shim.
- The workspace/session tree is not rendered in the rail. Session navigation moves to a transient switcher.
- The rail owns global session navigation/attention entry points, not archive browsing.
- The rail uses vanilla DSH's 36x36 control-seat rhythm; Material search/add/activity glyphs are optically sized at 22/24/20px.
- No spec-level keyboard chords are assigned in v0. Durable command ids are separate from host/platform keymaps.

## Upstream seams

v0 deliberately keeps upstream `AppFrame`. Public source at `47f943859bef60e4160492346772ded9b24f765a` establishes:

- `sidebar` is a whole-surface single slot.
- `sidebar = 0` resolves to the fixed 56px control rail; the sidebar never concedes to 0px.
- the vanilla collapsed rail uses 36x36 control seats in the 56px track;
- `ctx.sessions.list` is the metadata authority for visible session rows;
- `ctx.workspaces.list.archivedSessionIds` is the archive authority;
- `ctx.sessions.search()` is optional message-content search and is not the canonical corpus.

The browser artifact follows the rc.6-compatible namespace-loader shape already physically dogfooded by `dsh-matugen`: named namespace exports, no default export, and one `window.__ModuleLoader__.load(...)` artifact.

## Session projection

The switcher derives rows from `ctx.sessions.list` + `ctx.workspaces.list` only. It mirrors upstream top-level navigation semantics:

- archived sessions are excluded;
- subagent-origin children are excluded from the top-level switcher;
- blank sessions are hidden except for the selected blank session;
- workspace membership/order comes from `workspace.sessionIds`;
- loose sessions trail under `Ungrouped` by recency.

Search is an in-memory fuzzy projection over already-visible metadata (title/workspace/cwd/agent preset). It does not maintain a second session index and does not require the opt-in full-text provider.

Workspace paths are shown once at group level where possible rather than repeated under every row. A row uses agent preset as its preferred secondary metadata; a distinct cwd remains available when it adds information.

## Sessions and Activity

The transient surface has two explicit modes:

- **Sessions** shows the complete product-visible projection and can start a New Session.
- **Activity** applies `overviewGroups()` to the same projection and shows current/running/completed/pending-interaction rows.

Activity remains an Activity projection while searching. Entering a query cannot silently switch it back to the full Sessions corpus.

The current Session is indicated once by the status column; the older duplicate leading-dot marker is not rendered.

## Rail geometry

The application rail keeps AppFrame's 56px track and aligns its control seats to the vanilla collapsed rail at 36x36px.

Google Material Symbols Rounded paths are embedded for the three `dsh-rice` controls. Physical dogfood showed that equal SVG viewport sizes produced unequal optical ink sizes, so v0 uses:

```text
Sessions search  22px
New Session      24px
Activity         20px
```

The upstream Settings control remains upstream-owned. The optical compensation affects only glyph presentation; it does not enlarge the vanilla control-seat geometry.

See `THIRD_PARTY_NOTICES.md` for the Material Symbols Apache-2.0 attribution.

## Commands and input

The v0 command ids are:

- `quickSwitcher`
- `sessionMruNext`
- `sessionMruPrevious`
- `sessionOverview`

No fixed `Ctrl+K`, `Ctrl+Tab`, or `Ctrl+Space` bindings ship. Browser/OS/IME collision auditing belongs to a later platform keymap layer. Pointer/touch rail buttons are first-class entry points in v0.

The switcher itself supports local keyboard navigation: Escape closes, ArrowUp/ArrowDown move the active row, and Enter opens it.

`sessionOverview` currently opens the same transient surface with the Activity lens. A richer card overview is intentionally deferred.

## Lifecycle

The original `ui-sidebar` row must be disabled. `dsh-rice` declares the same child seats (`sidebar.workspaces`, `sidebar.settings`, `sidebar.footer.action`) so existing feature registration lifecycles remain valid; v0 deliberately does not render the workspace-browser child seat, while it does render the existing Settings/footer occupants in rail posture.

The rail reads AppFrame's `collapsed` owner prop and uses a layout effect to toggle only an actually expanded sidebar closed. This makes the v0 56px posture idempotent across plugin reloads without inventing a second layout state.

A linked checkout may change on disk while a running DSH Web process still holds older Host/client module state. Current dogfood therefore treats a DSH process restart after changing plugin heads/build artifacts as the clean provenance boundary.

## Theme relationship

`dsh-rice` uses ordinary DSH semantic theme variables and does not own palette production. It works with stock DSH themes.

`dsh-matugen` is an optional, independent semantic theme provider. When both are composed, `dsh-matugen` updates DSH's semantic `--dsw-*` tokens and `dsh-rice` repaints through those same variables. Neither package imports or configures the other.

## Verification boundary

`npm run check` covers the repository-local behavior and browser artifact. Physical dogfood with `@deepseek-ai/dsh@0.1.0-rc.6` has additionally verified real Web composition, the 56px rail, Material SVG deployment, Settings/footer survival, full-width Chat and unaffected Trajectory presentation.

GitHub Actions runs that fail before any step starts because of account billing/spending limits are treated as infrastructure failures rather than code-test evidence.
